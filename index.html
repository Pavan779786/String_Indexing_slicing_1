Indexing: one character at a time

Positive indexes start at 0, not 1. Negative indexes start at -1 for the last character, so s[-1] is always the end, whatever the length. For a string of length n, index -k is the same seat as n-k.

# s = "PYTHON" (len(s) is 6) s[0] # 'P' s[-6] # 'P' s[5] # 'N' s[-1] # 'N' len(s) - 1 # 5 ← last valid positive index

Index finder

Slicing: s[start:stop:step]

start
First index to take. Blank means "from the beginning" (or the end, if step is negative).
stop
The index to stop before. It is never included. s[1:4] gives indexes 1, 2, 3.
step
How far to jump each time. Default 1. Negative walks backwards. Never 0.

The trick: think of the numbers as pointing at the lines between tiles. stop is the wall where you halt, so the tile after that wall stays out.

Negative steps: slicing backwards

With a negative step, Python starts at the end and walks left, so the defaults swap: start becomes the last character and stop becomes "before the first". That is why s[::-1] reverses a string, and why s[1:4:-1] is empty: you cannot walk left from 1 to reach 4.

Rules that trip people up

Slices never crash
Out-of-range slice values are trimmed silently. "PYTHON"[2:99] gives 'THON'. Only single indexing raises IndexError.
Strings are immutable
You can read s[0] but not assign to it. Build a new string: "J" + s[1:].
Split at any point
s[:k] + s[k:] always rebuilds s, for any k.
